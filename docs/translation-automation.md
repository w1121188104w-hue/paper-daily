# 自动翻译使用与保护规则

2026-09-10。用户已授权全库翻译、每日自动翻译及正常API消费，并明确不需要逐篇校对。代码通过219项离线测试；远端启用和首次实际运行结果将在完成后补记。

## 平时怎么用

直接打开[论文日历](https://w1121188104w-hue.github.io/paper-daily/)。后台每天北京时间08:17采集，13:17按需补查，两次采集步骤之后都检查待翻译论文，保存后更新同一网站。无需打开电脑，也无需在网页输入密钥。GitHub可能排队，时间不是准点保证。

中文为未经逐篇校对的机器翻译，请以英文原文为准。只处理研究候选的现有英文标题、摘要；来源缺少的摘要不补写，目录、更正、撤稿不进入这轮翻译。已有完成中文不重译。原文以后真正变化时，只有变化的字段产生新翻译任务。

## 启停与维护

`JOURNAL_TRANSLATION_ENABLED=true`允许自动翻译；改为`false`暂停未来翻译，不影响采集或已发布网站，不取消正在运行的任务。Secret `DEEPSEEK_API_KEY`仍只交给翻译步骤，不读取或复制到本机。开关和密钥不要混淆。

存量入口是GitHub Actions中的 **Translate existing library automatically and publish**。日常无需手动启动。与采集和发布共用生产排队锁，禁止强推和覆盖冲突；所有流程不监听数据推送，不会循环触发。

每批最多10篇，依次请求；存量单轮最多1000次/60分钟，每日模式两个时段合计最多500次/北京时间自然日，单轮30分钟。单篇输入20,000字节、批次100,000字节、单次输出4,096 tokens。原文不截断，无自动付费重试。额度用于防止程序失控，不是DeepSeek账户的硬性金额上限。有限时长退出时，未请求论文留给后续日程。

正式请求前，先把论文/字段的原文指纹推送到远端请求登记；只有上传成功才调用API。每批结束后把合格译文、字段失败状态、用量一起保存上传。中断遗留的登记会阻止新机器再次请求同一原文，即使无法确定当时是否扣费。代价是最多一批未真正请求的论文可能保守暂缓，需核实后处理，不能清空登记强行重跑。

仅自动检查返回格式、中文、长度、数字和原文指纹，不进行第二轮AI校对或人工润色。失败字段不保存模型正文，已有中文不删除。账号、余额、模型异常或连续三个返回格式错误暂停翻译；网络问题停止本轮并暂缓已请求论文，下一轮只继续未请求论文。异常提醒在已成功译文发布之后独立报告，不伪装全部成功。

公开登记仅位于`data/journal-store/automation/translation-state.json`，含任务指纹、状态、时间和用量，不含密钥、原文或未采用译文。这是正式历史白名单以外唯一允许自动提交的运行状态文件；不得提交整个`data/`。网页仅发布原有精简白名单，不包含登记。丢失或损坏登记必须停止，不得当成空记录。

只读查看：`node scripts/translate-library.js --status`。付费命令只允许已开启的GitHub默认分支后台运行。本机无需密钥。失败后先看运行摘要与登记，不要点击旧试译流程重复翻译。
