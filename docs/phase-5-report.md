# 第五阶段：期刊论文的本地只读界面

完成日期：2026-09-07。

## 现在可以做什么

此前的采集、存储和翻译模块已接到一个可用的本地网页入口。沿用原网页的绿色主题、日历格子和论文卡片，不改动旧 arXiv 页面和服务。

- 首页按月查看论文，支持上月、下月、回到本月，突出北京时间的今天。
- 日历按“首次发现日期”归档，同一篇论文即使有两个来源，也只算一篇。发表日期单独展示。
- 点击日期查看当天论文；返回日历会保留期刊、分类和关键词。
- 快捷选择 AER、JAR、JAE、CAR；下拉菜单覆盖全部19刊，另有四类学科筛选。
- 可搜索中英文标题、摘要、作者、DOI、期刊和日期。关键词与期刊、分类、日期条件可以叠加；多个空格分开的词需要都匹配。
- 合格中文标题优先，英文标题保留；合格中文摘要和英文摘要可以切换。未翻译时直接读英文，缺摘要时如实说明。
- 翻译失败或原文更新后，旧中文只在明确标注的折叠区域中保留，不作为当前译文。搜索也会匹配这些保留的旧中文。
- 作者保留原顺序，超过4位可展开全部；展示来源、DOI、发表日期和卷期页。每页最多20篇，避免一次铺开过多卡片。

首页下方的论文列表搜索的是**全部日期**，不局限于当前显示的月份；日历数字则只展示对应日期的匹配数量。日期页的搜索始终限定在所选发现日期。

分类选择会限制期刊菜单，不相容的旧期刊选择会清空。点击快捷期刊会切到该刊并清空分类，但保留搜索词；“全部19刊”同样保留搜索词。“重置筛选”清空期刊、分类、关键词，日期页仍留在原日期。

## 怎样打开

在项目目录运行：

```powershell
node scripts/journal-preview.js
```

然后打开 [本地只读预览](http://127.0.0.1:4317/)。这个地址只在自己的电脑上、且预览程序运行时可用，不是已部署的网站。

如果端口已被其他程序占用，可显式选择另一个端口：

```powershell
node scripts/journal-preview.js --port 4318
```

结束预览，在启动它的终端按 `Ctrl+C`。不用运行旧的 `npm start` 或 `npm run dev`。

如果电脑已能使用 npm，`npm run journals:preview` 是等效快捷命令；提示“找不到npm”时使用上面的 node 命令即可，不用改配置。

你也可以只检查数据是否能被网页读取，不启动网页：

```powershell
npm run journals:preview:check
```

当前正式论文库尚未初始化，所以检查结果为0篇、0次已保存采集。这不是“19刊都没有论文”。本轮没有替你采集真实数据，也没有向正式库塞入演示论文。

以后按第三阶段流程手动采集并保存，或按第四阶段流程保存翻译后，在页面点击“重新读取本地数据”即可看到更新。这个按钮**只读本地文件**，不会联网抓取论文或调用 AI。

## 怎样看采集状态

“采集概况”显示最近一次已保存的采集时间、实际期刊范围、回查的发表日期范围，以及新增/更新数。只检查AER时会明确显示1/19刊，不会说成全部期刊成功。

日历与日期页按所选期刊、当天的最新已保存记录计算双源完成情况。后一次失败不会被同一天较早的成功掩盖；没有运行记录时显示“未采集”，不因论文数为0就显示成功。搜索词只改变论文数量，不改变运行日志状态。

如果本地还有较新的未提交采集尝试，页面顶部会提醒“未能保存”或“尚无结果，需核查”；不会根据一份开始记录猜测任务仍然正常运行。无法读取尝试记录也会提醒，而不隐藏为成功。

翻译版本保存时间和采集时间分开，导入中文不会冒充又采集了一次。双源完成仅表示本轮数据源查询完成，不保证期刊所有论文均已被数据库收录。

## 本轮安全边界

新入口使用独立的只读预览服务，未改旧服务启动逻辑；旧 arXiv 功能的代码保留但不通过新入口开放。

- 不读取密钥设置，不触发旧首页的自动刷新，不提供采集、翻译或设置写入按钮。
- 仅监听本机地址，拒绝其他网站的跨域来源和非本机主机名，只接受读取请求。
- 只开放两张新页面、所需样式/脚本和经过校验的网页数据，不开放整个仓库或数据目录。
- 网页数据采用字段白名单，不包含原始来源页、内部文件路径、翻译工作批次或错误堆栈。
- 外部论文文字按普通文本展示；DOI链接固定生成到 `doi.org`，不直接使用来源中的任意网址。
- 首次读取失败不生成假的零条结果；再次读取失败会保留本页上次成功的内容，并明确提示不是最新数据。

## 验证情况

全套自动化测试：132项通过、0项失败，其中本阶段新增35项。

新增测试包括：双源去重计数、北京时间日期、闰年与跨年、组合搜索、筛选联动、日期导航、双语摘要切换、旧译文标注、作者展开、分页、空库及损坏库、未提交尝试提醒、敏感字段排除、真实本机HTTP响应及只读访问限制。

页面交互使用轻量模拟页面对象执行真实渲染函数的单元测试；HTTP检查使用临时论文库。测试数据没有写进正式库。新入口的首页实际响应为200。

依照网站构建技能，保留原有界面风格，并补充空白、失败、加载状态、键盘焦点、原生表单标签及窄屏布局。**尚未做真实浏览器截图、点击和手机视觉验收**，这些单元测试不能替代实际排版检查。

## 代码入口及后续安排

新界面在 `public/journals/`，通过 `scripts/journal-preview.js` 启动；网页数据整理在 `src/services/journalPresentation.js`，只读路由在 `src/journalPreviewServer.js`。

这是本地预览，不是已经完成的 GitHub Pages 发布包。界面使用相对链接，便于下一阶段接入静态发布；目前 `data.json` 和复用的 `base.css` 由只读服务提供，不能直接把这个文件夹上传就认为可用。

下一阶段准备 GitHub 自动运行及静态发布流程，先编写和验证相关代码。真正配置凭据、推送、开启定时运行或上线前，仍需明确确认。之后进行完整的浏览器、真实采集及失败恢复验收。

本轮未配置密钥、未部署、未推送，也未开启任何定时任务。
