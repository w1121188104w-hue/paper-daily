# 目录基线与两类提醒

## 当前实现

- 每个目录记录来源网址、已核对卷期、论文 DOI/标题/链接集合、原始采集时间、输入文件校验值。
- 目录回执核验通过后自动更新基线；论文缺摘要不会让已经核对完整的目录永远重复提醒。
- 读取失败、分页缺口、未匹配文章链接、目录核对未完成、错刊身份均不能推进基线。明确的空目录可保存零条；没有读到内容不等于空目录。
- 旧卷期、较旧导出不能把新基线倒退。历史卷期采集不能刷新“最新一期”巡检期限。
- 发现服务默认读取已保存基线，无需每次手工提供；目录已知论文不会因尚缺摘要而反复触发“新论文”。
- 历史搜索结果不能直接更新已采集基线；正式发现已改为三源，不再发起付费搜索。

## 网站与插件

**发现更新**：有证据的新增线索，进入现有日常增量目录队列。

**到期巡检**：没有基线，或距上次成功采集已到期限。默认 14 天，也支持 7 天。它不是发现新论文，不会自动加入日常队列。用户选择现有“全刊巡检”按钮执行。

网站显示各目录核对时间、卷期、记录数及下次巡检时间。无基线显示“目录数量未确认”，不显示误导性的零篇。静态网站在浏览器中重新计算到期时间，不必等新部署才变为到期；此过程没有网络/付费 API 调用。

旧提醒/回执格式继续可读；没有基线的历史记录不会被自动视为已核对完成。基线导入不会假造全刊巡检完成回执，也不会清除旧提醒。

## 复用旧采集结果（离线）

在仓库根目录执行（先去掉 `--save` 可只预检）：

```powershell
node scripts/seed-catalog-baselines.js --input "导出的详情结果.json" --interval 14 --save
```

可重复传 `--input`，按原始采集时间合并。程序从 `catalog.pages` 重放目录证据及缓存核对，不信任导出的顶层 `papers` 或成功标志；不读取 Key、不重新调用 DeepSeek、不导入正式论文。

复用最近七天内的真实搜索探针结果：

```powershell
node scripts/replay-saved-discovery.js --input "已保存的搜索报告.json" --save
```

只处理成功的智谱实测响应，拒绝 DOI 对照组和过期报告，不调用新的付费请求。不修改来源监测时间，不能伪装成刚刚运行了三源。重复证据去重。

基线和提醒保存在 `data/collection-workflow/state.json`，沿用原工作流写入锁，与代码一并纳入正式发布。上面的历史报告重放仅作离线工具，不在定时流程运行。
