# 正式采集闭环 1.1

新版以 [三个独立采集分支](unified-collection-flow.md) 为准：自动来源、本地 Python 和插件各自推进；所有新内容进入共用 DeepSeek 原文审核，已有数据无需等待其他分支。插件增加 Python 启动、暂停、继续和剩余任务交接。

## 自动链路

1. GitHub 每日两次执行三源增量发现，并读取官网公开目录、RSS 和文章页。不调用付费搜索。
2. 官网目录必须核对期刊身份、完整分页和文章链接。动态内容、验证页、重复分页、请求失败均保留待办，不能当作“没有文章”。
3. RSS 可提供 DOI、标题和明确摘要。它只代表部分清单，更新时间不充当发表日。候选经过共用 DeepSeek 核对和程序原文复核后，才可新增或补全；身份冲突保留待办。
4. AER 等成功直读的完整目录保存原始卡片证据；24 小时内且没有更新信号时，插件复用这些证据，不再打开同一目录。能直接取得的完整摘要入库后不再进插件详情队列。
5. 用户点击一次增量或全刊巡检。插件自动读取剩余目录、DeepSeek 原文核对、按 DOI 与已有库去重、打开未完成论文、采集摘要和现有作者单位、原文核对。
6. 只有验证/异常需要人工介入。验证码由用户处理，插件每 15 秒仅检查是否恢复正常页面，不点击或绕过验证。自动打开失败时仍可手动打开，再选“读取本页并继续任务”。
7. 采集期间已核对的部分内容即可独立提交；原始导出先保存在浏览器和本机。同一提交重试复用固定内容，断线不会导致丢失或重新采集。
8. 本机重放字段证据、合并去重、上传正式资料与持久翻译队列。不存在本地翻译步骤。
9. GitHub 使用唯一的翻译器与 DEEPSEEK_API_KEY，只处理批次论文的新增/缺失中文。成功字段不重译；收费前远端登记，计费未知或校验失败按已有账本规则保留。
10. GitHub 构建并发布；本机自动对照网站批次 ID、输入哈希、本次发布 ID 和云端处理回执，才显示“已发布”。翻译暂缓或采集缺失单独显示，不冒充全部成功。

## 用户操作

首次配置运行 `start-workflow.cmd`。日常打开扩展即可使用；如果显示未连接，点击“启动本机服务”，连接成功后再启动 Python 或插件采集。插件采集时保持面板开启；Python 采集和已经提交的批次可在关闭面板后继续。

Windows 启动器现在会注册当前用户的两个计划任务（正式流程、原文核对）。登录时自动启动；进程意外退出后由一分钟恢复触发器重新启动。正常运行时忽略重复触发，并使用进程锁和端口校验防止重复实例。后台进程由 Windows 计划任务管理，不依赖启动命令窗口或 Codex 的生命周期。任务使用当前用户的普通权限，不保存登录密码，不重新配置 Key，也不自动新建采集批次。

安装时通过现有加密配置的文件句柄解析实际数据路径，并把非机密路径传给两个任务；这兼容桌面应用对 AppData 的虚拟化。后台任务和启动器复用同一份配置、批次、缓存和计费账本，不复制或重新初始化它们。实际路径可在计划任务的 `-DataRoot` 参数查看，日志也位于该路径下的 `PaperDailyWorkflow/service-logs/`。仅设置服务子进程的数据目录，不修改系统环境变量。

计划任务通过本机编译的无控制台 Windows 启动器运行；PowerShell 和 Node 子进程都显式禁止创建控制台，而非仅依赖 `-WindowStyle Hidden`。启动器等待工作进程结束并传递退出码，保留自动恢复；标准输出/错误流持续丢弃，诊断仅使用固定事件日志。启动器按源码哈希保存在实际数据目录的 `PaperDailyWorkflow/service-host/`，升级不会覆盖正在运行的程序，也不改变 Windows Terminal 的全局设置。

这台电脑睡眠、关机或注销时服务仍不可用；登录/唤醒后由 Windows 恢复。配置损坏、端口被其他程序占用等故障不会靠强杀未知进程处理。只含时间、进程号和固定错误阶段的日志位于 `%LOCALAPPDATA%/PaperDailyWorkflow/service-logs/`。运行 `scripts/manage-workflow-service.ps1 -Mode Status` 可查看任务状态。

如需关闭自动启动/恢复，运行 `disable-workflow-autostart.cmd`；它不强制中断正在处理的批次。`stop-review.cmd` 停止核对服务时也会停用该服务的自动恢复；核对正在执行则拒绝关闭并恢复原来的任务设置。点击插件的“启动本机服务”或再次运行 `start-workflow.cmd` 会重新启用两个服务。核对缓存、持久调用额度、未知计费保护和 GitHub 翻译账本均保持不变。

日常增量只处理有提醒的目录；每周或半月可手动全刊巡检最新一期和在线发表。无提醒不代表无新论文，全刊巡检不回溯所有历史卷期。

正常路径不再要求导出、进入详情、提交结果、确认本地翻译或点击发布。高级区只保留故障恢复与备份。旧测试状态不删除，也不再作为正式入口显示。

## 失败与恢复

本机服务重启可恢复已经提交的批次，不会自行开启新的浏览器采集。同步、上传和发布的暂时故障按最长十分钟的退避间隔继续重试；其他处理阶段连续失败最多自动恢复 5 次，然后保留错误阶段等待检查。云端正在写入时，本机等待后自动续传，采集与审核仍可继续。云端任务按每批最多 100 次请求、最多 6 轮进行有界续跑；原有翻译计费/未知结果保护优先，不会因重启清零。

原文核对失败、无 DOI、身份冲突、不完整目录均保留原始证据和待办。原文没有摘要就留空，不生成。JPE Just Accepted/图片摘要停用；正常文字摘要保留。作者单位不扩展采集能力。

## 运行边界

- 发现：`collection-discovery.yml`，北京时间 08:17、12:17，GitHub 不保证准点。
- 云端翻译和发布：`collection-publish.yml`，上传后自动触发；每小时第 43 分钟检查续跑队列。
- 手动部署：`deploy-pages.yml`；上线检查：`site-smoke.yml`。
- 开启新版发现、云端发布和 Pages；旧采集、摘要搜索、智谱、SerpAPI 及旧翻译开关保持关闭。
- 官网请求遵守 robots、限流、白名单和页数上限，不绕过登录、验证或付费墙。

## 数据与密钥

`data/collection-workflow/state.json` 保存提醒/回执；`official-catalogs.json` 保存可追溯官网卡片及 RSS 检查状态；`publication-queue.json` 只存论文 ID 和任务状态，不存浏览器完整原文或 Key。

原始浏览器批次保存在本机 `%LOCALAPPDATA%/PaperDailyWorkflow/<批次 ID>/`。本机核对 Key 仍由原加密配置保存；正式流程服务不解密翻译 Key。GitHub Secret 注入来源审核和翻译步骤，分别使用独立的持久计费账本。服务仅监听 127.0.0.1:17328，并核对固定扩展 Origin。

历史快照、原始出处、已付费账本、已完成译文和旧导出不删除。被移除的旧入口可从 Git 历史恢复。
