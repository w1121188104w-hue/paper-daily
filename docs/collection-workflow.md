# 正式采集闭环 1.0

## 自动链路

1. GitHub 每日两次执行三源增量发现，并读取官网公开目录、RSS 和文章页。不调用付费搜索。
2. 官网目录必须核对期刊身份、完整分页和文章链接。动态内容、验证页、重复分页、请求失败均保留待办，不能当作“没有文章”。
3. RSS 可提供 DOI、标题和明确摘要。它只代表部分清单，更新时间不充当发表日。已有 DOI、期刊、标题完全一致且缺摘要时可直接补原文；新条目或身份冲突只产生目录提醒。
4. AER 等成功直读的完整目录保存原始卡片证据；24 小时内且没有更新信号时，插件复用这些证据，不再打开同一目录。能直接取得的完整摘要入库后不再进插件详情队列。
5. 用户点击一次增量或全刊巡检。插件自动读取剩余目录、DeepSeek 原文核对、按 DOI 与已有库去重、打开未完成论文、采集摘要和现有作者单位、原文核对。
6. 只有验证/异常需要人工介入。验证码由用户处理，插件每 15 秒仅检查是否恢复正常页面，不点击或绕过验证。自动打开失败时仍可手动打开，再选“读取本页并继续任务”。
7. 采集和核对结束自动提交；原始导出先保存在浏览器和本机。同一提交重试复用固定内容，断线不会导致丢失或重新采集。
8. 本机重放字段证据、合并去重、上传正式资料与持久翻译队列。不存在本地翻译步骤。
9. GitHub 使用唯一的翻译器与 DEEPSEEK_API_KEY，只处理批次论文的新增/缺失中文。成功字段不重译；收费前远端登记，计费未知或校验失败按已有账本规则保留。
10. GitHub 构建并发布；本机自动对照网站批次 ID、输入哈希、本次发布 ID 和云端处理回执，才显示“已发布”。翻译暂缓或采集缺失单独显示，不冒充全部成功。

## 用户操作

首次配置后，运行 `start-workflow.cmd`，打开扩展，点击开始。采集时保持面板开启；上传之后可关闭面板，本机服务继续核验。

日常增量只处理有提醒的目录；每周或半月可手动全刊巡检最新一期和在线发表。无提醒不代表无新论文，全刊巡检不回溯所有历史卷期。

正常路径不再要求导出、进入详情、提交结果、确认本地翻译或点击发布。高级区只保留故障恢复与备份。旧测试状态不删除，也不再作为正式入口显示。

## 失败与恢复

本机服务重启可恢复已经提交的批次，不会自行开启新的浏览器采集。连续后台失败最多自动恢复 5 次，然后保留错误阶段等待检查。云端任务按每批最多 100 次请求、最多 6 轮进行有界续跑；原有翻译计费/未知结果保护优先，不会因重启清零。

原文核对失败、无 DOI、身份冲突、不完整目录均保留原始证据和待办。原文没有摘要就留空，不生成。JPE Just Accepted/图片摘要停用；正常文字摘要保留。作者单位不扩展采集能力。

## 运行边界

- 发现：`collection-discovery.yml`，北京时间 08:17、12:17，GitHub 不保证准点。
- 云端翻译和发布：`collection-publish.yml`，上传后自动触发；每小时第 43 分钟检查续跑队列。
- 手动部署：`deploy-pages.yml`；上线检查：`site-smoke.yml`。
- 开启新版发现、云端发布和 Pages；旧采集、摘要搜索、智谱、SerpAPI 及旧翻译开关保持关闭。
- 官网请求遵守 robots、限流、白名单和页数上限，不绕过登录、验证或付费墙。

## 数据与密钥

`data/collection-workflow/state.json` 保存提醒/回执；`official-catalogs.json` 保存可追溯官网卡片及 RSS 检查状态；`publication-queue.json` 只存论文 ID 和任务状态，不存浏览器完整原文或 Key。

原始浏览器批次保存在本机 `%LOCALAPPDATA%/PaperDailyWorkflow/<批次 ID>/`。本机核对 Key 仍由原加密配置保存；正式流程服务不解密翻译 Key。GitHub Secret 只注入翻译步骤。服务仅监听 127.0.0.1:17328，并核对固定扩展 Origin。

历史快照、原始出处、已付费账本、已完成译文和旧导出不删除。被移除的旧入口可从 Git 历史恢复。
