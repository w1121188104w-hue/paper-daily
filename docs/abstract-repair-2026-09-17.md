# 2026-09-17 集中补查与出版社定向搜索

## 已上线的集中补查

日常任务仍按原来的重试日期处理。手动触发 daily-collect 时可选
`retry_missing_abstracts_now`，仅提前处理未解决的 `missing_abstract`。
命令行对应 `--retry-missing-abstracts-now`；定时事件不能启用这个选项。
不修改历史重试时间，不重新搜索完整记录，不绕过来源限流、账本或免费额度。

## 出版社定向搜索

三源和已知原始页面仍优先。进入智谱搜索时，先以 DOI 和标题分别搜索期刊对应出版社域名，
例如 Elsevier → ScienceDirect、CAR/JAR → Wiley。其后保留普通标题搜索和 RePEc 搜索。
搜索词最多 70 字；过长 DOI 不截断后冒充完整 DOI 用于官网定向查询。
智谱联网整理请求同时收到期刊官方站点提示。

适配器将定向查询转换为官方 `search_domain_filter` 参数，而不只依赖检索词中的 `site:`。
普通查询不继承这个限制。Chat 响应的 `web_search` 与旧兼容字段 `search_result` 都被读取并按 URL 去重；
模型回答 JSON 内自称的检索证据不予采用。参数和字段依据：
[联网搜索文档](https://zhipu-ef7018ed.mintlify.app/cn/guide/tools/web-search)、
[对话补全文档](https://zhipu-ef7018ed.mintlify.app/api-reference/模型-api/对话补全)。

`site:` 只是检索提示，不能视作论文身份或摘要真实性证明。
仍须验证来源域名、标题、DOI、完整 Abstract 边界和逐字对应关系；不接受模型自编摘要、
截断片段或仅有一个链接的结果。不会为读取受限页面绕过访问控制。
明确的独立行语言标签 `en`/`English` 和编号引言标题不属于摘要正文；提取时识别这些边界。
英文 Abstract 后面的 CAR 法文 RÉSUMÉ 也不能一并保存为英文摘要。

## CAR 标题补查

已知双语标题的 DOI 核对保留两分钟预算，每篇最多一次、最多八秒。
单篇不存在或暂时超时不阻断后面的论文；来源返回 401/403/429 或要求稍后重试时停止。
耗尽预算必须标为未完成，保留原文等待再次核对，不猜测英文标题边界。
清单返回的相同双语长标题不算英文边界证据，仍需执行单篇 DOI 核对。

## CAR 仅法文摘要的英文原文补查

名册规则 v5 将 CAR 明确以 `RÉSUMÉ` 开始、没有英文段落的记录列入缺英文摘要待办。
旧 v1–v4 名册仍按原规则重读，历史文件不重写。法文原文不先清空，也不交给 AI 反译冒充英文原文。
现阶段只允许已核验的智谱出版社原文证据替换：同 DOI/标题、官方 Wiley 域名、完整 Abstract 边界、
原始检索正文哈希和逐字相等均须通过检查。旧来源和译文保留，英文补回后中文摘要进入原翻译队列。
后续采集优先保留这份有证据的英文，不因法文更长而回退。未找到时继续保留待办和退避重试。
公开页面同样将仅法文记为 `english_missing`，显示法文语言标签、重试时间并计入待补数量。
翻译就绪筛选暂缓此类法文摘要，但允许英文标题先译；旧快照完整翻译队列不变，保持历史可重读。

## 翻译数字保留

DeepSeek 请求中附带由待译原文机械提取的数字清单，与导入检查使用相同规则。
提示模型在对应正文中保留年份、金额及术语中的数字，不擅自修正原文年份、不把数字堆在文末。
仅对本次请求字段生成清单；没有英文摘要时不会增加摘要请求。原有译文检查和重试账本不变。
新登记记录数字保留请求方案 `numeric_preservation_v1`。对旧方案已结算的格式失败允许使用新方案恢复，
每种方案最多三次、同一原文字段合计最多六次，仍有三十分钟冷却。
旧账本原样保留并通过 `retry_of` 关联；成功字段、未结算请求及网络结果不确定的请求均不自动重发。

## 原文机械提取与搜索账本体积保护

搜索工具正文已经包含同一 DOI/标题、正确期刊来源且边界完整的唯一英文 Abstract 时，直接机械复制。
不再让模型重复抄一遍作为保存前提；模型回答为 null 或改写也不会影响对独立原文的识别。
只有 snippet、正文截断、身份不符或多个真实来源摘要相冲突时仍不采纳，不用 AI 猜测补齐。

账本读取使用 GitHub Contents object 媒体类型；超过 1 MB 导致 content 为空时，只按同一个 blob SHA
读取原始账本，核对 SHA、长度和结构后再继续。缺文件、错误版本、截断或超出本程序 5 MB 上限均停止，
不能重置历史用量；写入继续保留原 SHA 的并发保护，不跟随响应提供的 download_url。
依据：[Contents 大文件行为](https://docs.github.com/en/rest/repos/contents#get-repository-content)、
[Git Blob 读取接口](https://docs.github.com/en/rest/git/blobs#get-a-blob)。

## 智谱网页阅读小范围验证（未接入每日流程）

## RePEc 期刊目录定位已知论文

已核实 JFE、RP、JAE、JCF、AOS 的公开 RePEc 期刊目录地址。
此目录只用于定位库内缺摘要论文，不列为第四个独立发现源，不改变 Master List 的来源统计。
读取时核对目录的期刊全名和 ISSN；只取相同系列的正式文章链接，不读取工作论文或其他期刊路径。
标题标准化匹配只产生线索，最多核验三个同名候选。文章页仍须通过现有 DOI、标题、期刊、作者及
页面正文摘要与 citation_abstract 一致性检查；不从目录文字、搜索片段或模型回答生成摘要。

每轮每刊目录只读一次，空结果及访问失败也缓存。遵循已有 robots、限速和请求次数上限。
选定的缺摘要批次中，已有目录线索的论文优先处理，避免已知线索排在大量慢搜索之后错过运行时限。
这是排队提示，不是收录证明；不删除其他待办，不改变每篇论文的三源核对顺序，目录失败仍继续原流程。
三源和官网未补齐后，在付费搜索之前尝试目录；没有可靠结果仍回到智谱优先的既有流程。

（JFE 4、RP 6、JAE 4、JCF 1、AOS 1）；该实测未写正式库、未调用付费 API，不能视为已上线补齐数量。
目录自身也可能滞后，不以目录未列出为删除论文依据。
来源：[JFE](https://ideas.repec.org/s/eee/jfinec.html)、[RP](https://ideas.repec.org/s/eee/respol.html)、
[JAE](https://ideas.repec.org/s/eee/jaecon.html)、[JCF](https://ideas.repec.org/s/eee/corfin.html)、

## 验收边界

### 同名勘误不能借用原论文摘要

Crossref 对 10.1016/j.respol.2026.105588 明确提供 update-to / erratum，
指向 10.1016/j.respol.2026.105542；标题和作者相同并不意味着同一篇论文。
新增规范化保留 crossref_notice：原始 type、更新类型及关联 DOI。
只有指向不同且有效 DOI 的 correction/corrigendum/erratum 或撤回通知才派生已有通知类型。
updated-by、自身原位更新、版本变更及无效数据不把正常研究论文误标为通知。
旧来源记录不重写，摘要保持缺失，不借用被更正论文的摘要，也不宣称通知必然没有摘要。
这项识别本身不降低全库摘要缺失数量、不删除记录；原论文与通知在现有筛选中分别保留。
依据：[Crossref 更新通知说明](https://www.crossref.org/documentation/register-maintain-records/maintaining-your-metadata/registering-updates/)。

### 临时限流的有界恢复

HTTP 429 作用于整个来源站点，不能换论文 URL 提前重试。
优先遵守 Retry-After，最少冷却一分钟；服务器未提供有效时间则冷却五分钟。
每轮每个来源最多允许两次冷却后的恢复尝试，第三次收到 429 后本轮停止该来源。
恢复不阻塞等待线程，而是在之后处理其他待办时检查是否到期；总请求数和整轮时限仍生效。
结构化 API 的失败 Promise 在 429 时释放，避免冷却已结束却永久读到旧失败。
401/403 不按临时限流重试；不绕过认证、验证码或访问限制，不影响既有付费搜索账本。

代码测试通过不代表所有摘要已找到。必须继续核对正式库、运行报告与发布页面，
分别报告缺英文原摘要与未完成中文翻译；不能删除真实论文或编造摘要来归零。
