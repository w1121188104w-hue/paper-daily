## 怎样检查，数据从哪里来

使用本机只读页面和应用内浏览器，通过改变浏览器显示区域的宽度检查电脑、平板和手机尺寸。不是在实体手机、Safari或Firefox中测试。

先检查真实空库，确认显示“尚未采集”；再用25篇明确标有“验收测试／UI TEST”的虚构材料覆盖19刊、两页列表、多作者、长标题、各种翻译状态和故障状态。虚构材料只在独立验收服务的内存中，不写入正式论文库，不进入静态网页打包。没有访问测试材料中的DOI链接。

隔离验收工具位于 `scripts/qa/`，仅供开发检查，不是采集程序。网页顶部会显示验收环境说明。正常用户预览仍使用 `node scripts/journal-preview.js`。

检查结束后已恢复真实空库场景、重置浏览器尺寸，并关闭验收页面及临时服务；没有留下自动采集或后台验收任务。

本轮使用网站构建技能的本地验收流程，保留原有绿色日历／卡片风格，只修正操作和窄屏问题；未使用网站注册、托管或发布功能。

## 发现并修复的问题

| 问题 | 修复后的效果 |
| --- | --- |
| 日期页首次读取失败时，返回链接丢失月份和筛选 | 页面开始读取前就准备好返回链接；出错仍保留月份、分类、期刊和关键词 |
| 自动搜索删掉输入框末尾空格，难以接着输入第二个英文词 | 输入过程中保留空格和光标；另加入中文输入法组词期间不搜索的保护 |
| 用键盘翻页后，焦点落回整个网页 | 翻页后焦点移到论文列表标题，继续操作有明确起点 |
| 320像素窄屏中“10、11”等日期被拆成两行 | 调整日期圆标内边距并禁止拆行，复验两位日期保持一行 |

前三项补充了程序回归检查，窄屏日期另用浏览器截图和文字布局检查复验。中文输入法保护通过模拟组词事件的单元测试；未操作实体中文输入法候选框，不将其计为完整输入法兼容性验收。
