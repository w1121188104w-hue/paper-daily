# 第二阶段交接说明

更新日期：2026-09-07。对应“19刊名单 + 双源采集 + 统一结构 + 去重”的阶段范围。

## 先说结论

采集和合并的基础模块已经写好，并通过33项离线测试；对 AER 做了一次真实接口试抓，两源均成功。
现在还不是完整的网站：数据只在程序运行期间暂存，退出后不会留下正式论文库，旧网页也还没有接入新模块。

本阶段没有配置任何密钥，没有调用 AI，没有部署、推送或设置每日任务，没有改动原 arXiv 服务代码或用户的历史论文数据。

## 现在能做什么

- 认准19本期刊：用完整刊名、ISSN（期刊身份编号）和 OpenAlex source ID 查找，避免只凭缩写抓错刊。
- 每本期刊都查 OpenAlex 和 Crossref。一方失败，另一方已经取到的资料仍保留在本轮结果中；同时明确报告失败。
- 把两边的标题、摘要、作者和日期整理为同一种结构，保留原文与来源。
- 优先按 DOI（论文的稳定标识）合并。同刊缺 DOI 时，只用“规范化标题 + 第一作者 + 年份”精确匹配；只是相似的记录留待检查。
- 不把不同 DOI 强行合并，不把期刊冲突混在一起；不凭空补摘要或日期。
- 记住首次发现日期；原文变化时把旧译文标为“已过时”，没有摘要则标为“暂无摘要”。这里只标记状态，不生成翻译队列文件，也不调用翻译服务。

19刊为：TAR、AOS、JAR、JAE、CAR、RAS、AER、JPE、QJE、RES、JF、JFE、RFS、JCF、JIBS、RP、MS、JM、JOM。全名、分组和核验链接见 [期刊核验表](journal-verification.md)。

## 怎么检查

在仓库文件夹打开终端。以下命令需要已有 Node.js，无须额外安装本阶段的依赖。

### 1. 离线自检（建议先做）

```powershell
node --test
node scripts/journals.js
```

第一条运行自动测试；第二条检查本地期刊名单格式、校验位及编号是否重复。两条都不联网，不写论文数据。
如可以使用 npm，等价命令是 `npm test` 和 `npm run journals:check`。

### 2. 单刊联网试抓（可选）

```powershell
node scripts/journals.js --collect --journal AER --from 2026-08-01 --to 2026-08-31 --max-pages 3
```

它会向两家公开数据接口发送读取请求，只打印数量和两条样例。无需提供密钥。日期可以改成想查的出版日期范围；`--max-pages` 是每个来源最多读取几页，默认10页，每页最多100条。

如确实要查全部19刊，把 `--journal AER` 换成 `--all`。这会发出更多请求，可能较慢或被来源限流。不要为了试抓运行 `npm start` 或 `npm run refresh`，那是旧 arXiv 程序。

每次试抓都从空的内存集合开始，因此 `added` 只是“这次试抓获得的候选数”，不是正式日历的新增数。只有后续接入历史库，才能计算真正的每日新增。

### 3. 如何看结果

| 英文状态 | 通俗含义 |
| --- | --- |
| `success` | 所选期刊的两源都完成本轮读取，合并后有新增或变化 |
| `no_updates` | 两源都完成读取，但相对传入历史没有变化；不代表全世界没有新论文 |
| `partial_failure` | 部分读取失败、不完整或记录被拒收；仍有可用结果 |
| `full_failure` | 没有可用的新来源结果，不能当作“没有新增” |

任何一源达到页数上限、缺少下一页信息或重复返回同一页，都不会报告“完整成功”。失败状态的命令退出码为1；成功状态为0。

## 正式运行前仍需处理

1. **永久保存和安全更新尚未接入。** 下一阶段需要按年保存论文、记录每次运行、校验完整数据结构，并确保中途失败不会覆盖旧库。现在的原始返回页及来源快照仅在内存中保留。
2. **有候选记录不等于都是研究论文。** 实测中 Crossref 返回了标题为 `Front Matter` 的卷首资料。正式建库前应增加可审计的非论文筛选规则，同时保留对更正、撤稿等特殊记录的辨别能力。
3. **出版日期不等于数据库新增日期。** 两源的日期口径不同；仅回查最近60天的出版日期，不能保证找到更早论文的迟到记录或摘要补充。后续需加入定期深度回查和已知缺摘要论文的定向补查；本阶段未自动安排。Crossref 官方也建议持续同步时考虑创建、更新或索引时间，而不仅是出版时间。[Crossref 使用说明](https://www.crossref.org/documentation/retrieve-metadata/rest-api/tips-for-using-the-crossref-rest-api/)
4. **跨来源选字段采用启发式规则。** 先按同一来源的更新时间选择最近非空值，再优先选更完整、乱码更少的候选；不是 AI 对论文内容的判断。作者选择较完整的有序名单，只对精确同名且唯一的 ORCID 做补充。复杂公式、同名作者和冲突记录仍需要审查。
5. **验证范围有界。** 已核对19刊身份，但本轮只实测一本期刊的一个月份，没有证明19刊全量历史、各种分页极限或长期限流环境都已通过。未验证旧网站的端到端功能，也未加入自动化部署。

下一阶段建议顺序：先加非论文筛选与永久库的安全保存，再做每日增量和补抓日志。之后才接人工翻译导入、网页显示与定时发布。

## 给后续开发者的接口说明

入口是 `collectJournals(config, options)`，返回 `papers`、`audit`、`stats`、`source_results` 和总体 `status`。传入 `existingPapers` 才能计算跨次新增；函数本身不读写论文库。

各源统一记录在 `sourceNormalizers.js` 整理，`paperMerge.js` 负责纯内存合并。模块导入不启动服务。

| 论文主要字段 | 含义 |
| --- | --- |
| `id` / `doi` / `doi_url` | 稳定内部ID、规范DOI及链接；后补DOI不改变已有ID |
| `title_original` / `abstract_original` | 选用的英文原文，去标签和基础实体清洗 |
| `source_records` | 各来源版本，包含清洗文本、`raw_title`、`raw_abstract`、原始日期与来源时间 |
| `provenance` | 每个主要字段从哪里来；作者标识补充单独记来源 |
| `published_online_date` / `published_print_date` / `publication_date` | 分开的在线、印刷、普通出版日期；允许仅有年份或年月，不编造缺失部分 |
| `first_seen_date` / `last_checked_at` | 北京时间的首次发现日、ISO格式核对时间；不得拿出版日期充当发现日 |
| `title_zh` / `abstract_zh` | 中文译文，目前仅保留已有值 |
| `*_translation_status` / `source_text_hash` | 各字段翻译状态与原文哈希，用于后续判断是否重新翻译 |

新标题为 `pending`；摘要为空为 `no_abstract`；原文不变保留已有状态；有旧译文但原文变化为 `outdated`。`translation_model` 和 `translated_at` 保留已有信息，不制造新的翻译记录。

OpenAlex 使用精确 `primary_location.source.id` 和出版日期范围，游标翻页；每页限制100条。[OpenAlex 分页说明](https://help.openalex.org/api/paging/)
Crossref 使用 `/journals/{ISSN}/works`、出版日期和 `type:journal-article` 筛选；游标可能不变，按返回不足一页判断结束。[Crossref 使用说明](https://www.crossref.org/documentation/retrieve-metadata/rest-api/tips-for-using-the-crossref-rest-api/)

HTTP 默认30秒超时，最多3次请求；对429及部分临时错误退避重试。来源要求等待超过60秒时报告 `RETRY_LATER`，交给后续运行重试，不提前打扰来源。错误摘要不包含请求URL或远程响应正文。

本次保留原依赖和启动流程，只增加测试/检查脚本；`.gitignore` 只额外允许公开的 `data/config/journals.json`，其他运行数据和密钥文件仍应保持忽略。
