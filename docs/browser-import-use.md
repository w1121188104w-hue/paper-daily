# 插件结果到论文网站：本地导入闭环

作者单位暂不处理。线上定时采集、智谱搜索和 SerpAPI 不会因本入口而启动。

## 已接通的步骤

插件采集 → 插件调用本地 DeepSeek 核对 → 导出 JSON → 本地预检 → 导入版本库 → 复用已有 DeepSeek 翻译 → 构建原有网站。

本入口不自动部署。发布前必须取线上最新论文库和翻译账本作基线，不能将历史 worktree 的旧库覆盖线上。

## 用户操作

1. 在原扩展完成采集和核对，点“导出结果 JSON”。不要删除原始导出文件、插件缓存或本地翻译账本。
2. 双击项目中的 `start-browser-import.cmd`。选择导出的 JSON。默认操作一个独立本地工作库，不直接写线上库。
3. 先看预检结果；输入 `YES` 后才导入、翻译并生成网页。默认每次最多 10 个翻译请求，剩余可用同一文件继续执行；已完成的不重复翻译。已有 Key 自动复用，无需重填。
4. 网页目录生成后，可在本地预览。确认合并范围后再单独发布；不会自动恢复云端任务。

## 命令入口

`node scripts/browser-import.js --file "导出文件.json" --library "本地库目录"`

默认只预检，不写任何文件、不联网。正式保存追加 `--save`；构建网页追加 `--build "独立网页输出目录"`。

本机翻译入口（复用 Windows 加密配置，不在命令行传 Key）：

`powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/browser-import-local.ps1 -File "导出文件.json" -Library "本地库目录" -Save -Translate -MaxRequests 10 -Build "独立网页输出目录"`

全新库首次翻译才添加 `-InitializeTranslationLedger`。已有翻译历史但账本丢失时拒绝创建空账本，以免重复付费。

## 导入约束

- 只导入本次实际打开并核对的详情，不导入 export.papers 中上千条未采集候选。
- 从保存的原文块重放核对结果；不直接信任导出里的 reviewed_records、摘要状态或 AI 文本。
- 官方期刊路径/ISSN、目录卡片、详情标题/DOI相互核对。同 DOI 错刊、标题冲突和同批摘要冲突均保留报告，不强行覆盖。
- DOI 优先去重；无法验证的无 DOI 记录留在原导出中，尚不由此详情导入器写入。目录无 DOI 采集能力不因此删除。
- 旧论文只补原本为空的摘要，不改原有标题、日期、作者、摘要或译文。缺月份不捏造具体日期。
- CAR 英文标题只取页面中实际存在且可验证的英文标题。没有真实英文摘要则保持为空。
- 明确的非研究内容保留“其他”分类。现有翻译器只翻译研究候选；“其他”不会偷偷消耗翻译额度。
- JPE Just Accepted 目录及失败图片摘要记录排除；正常文字摘要保留。
- 来源 URL、采集时间、原文字段、请求指纹和导出文件 SHA-256 随版本保存。正文上下文、完整 AI 请求和 Key 不进入公开网页。
- 每次写入先校验完整快照，最后切换指针；旧快照保留。中断后原命令可继续，重复导入不重复写库。
- 本地翻译使用独立进程锁、持久请求预登记和原文哈希。状态不明的请求不会立即重发。
