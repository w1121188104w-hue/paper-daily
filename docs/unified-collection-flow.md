# 三个采集分支与统一原文审核

自动采集、本地 Python、插件分别取得数据后，独立推进审核、入库、翻译和发布。
任何分支的缺失字段、验证码或失败条目都不能成为其他已取得内容的整批屏障。
目录卡片与文章详情是不同审核对象，保留现有插件的 DeepSeek 原文选择、确定性复核、证据缓存及有限重试机制。

## 实现约束

- 三个分支共享论文身份、已有字段和待办；每个字段可分次补全。
- 新内容必须通过真实 DeepSeek 审核，模型只能选择已保存原文，程序重新验证后入库。
- 没有摘要的已核验元数据可以先发布；不得把缺失当成已确认没有摘要。
- 目录完整性、分页及期刊身份仍由程序核验；模型无法替代网页覆盖检查。
- 插件保留最终疑难处理能力，同时提供本地 Python 启动、进度、暂停/继续入口。
- Python 页面访问间隔至少 3 秒，检查点持久化，关闭面板不丢数据。
- 相同证据复用审核缓存；未知计费状态不自动重发；修改内容重新审核。
- 本机审核使用现有本机密钥，GitHub 审核/翻译使用现有 GitHub secret，界面和日志不包含密钥。
- 原始材料与审核失败持久保留；并发采集可进行，正式入库写入和 Git 提交串行化。

## 验收

覆盖三个分支独立发布、部分数据先入库、后续补全而不覆盖原文和翻译、重复提交幂等、审核失败不影响其他条目、进程中断续跑、插件原有功能回归与真实 DeepSeek 小范围调用。

用户补充的最终交付：验证通过后直接上线正式代码和服务，由助手重新加载浏览器插件，并从插件中启动本地 Python，确认采集、DeepSeek 审核和发布链路实际运行。仅完成代码或测试不算完成目标。

## 实际运行方式

前三行是独立入口，各自进入后面的公共处理，不需要等待其他入口完成。

| 步骤 | 做什么 | 谁负责 |
| --- | --- | --- |
| 自动采集 | Crossref、OpenAlex、Semantic Scholar、官网与 RSS 获取候选及原始证据 | GitHub 定时任务 |
| 本地补采 | 插件点“启动本地 Python 补采”；按未完成任务访问目录、在线发表、详情，至少间隔 3 秒 | 本机服务与 Python 浏览器 |
| 疑难补采 | Python 暂停/结束后点“用插件处理剩余任务”；复用已采内容与审核缓存 | 插件，必要时用户处理验证码 |
| 程序整理 | 检查期刊、文章身份、原文边界与重复记录，提出字段候选 | 三个入口共用校验程序 |
| 原文审核 | DeepSeek 核对字段分类，只能选择保存的原文；目录卡片与详情可分别审核 | 共用审核协议与缓存 |
| 再次校验及入库 | 程序重放选中的证据；允许只有部分字段先入库，后续只补空缺 | 本机/云端入库程序 |
| 翻译、发布 | 使用统一持久队列，已完成译文不重译；各批次独立发布 | GitHub |
| 后续补全 | 缺失字段留在共享清单，到期再试；不会把缺摘要当成原文明确无摘要 | 自动采集、Python、插件 |

首次安装 Python 可运行项目根目录 `setup-local-python.cmd`。服务通过既有计划任务在登录时启动；网页面板关闭不停止 Python。采集暂停会先保存当前页面，恢复时继续原任务；进程启动失败会记录错误阶段。浏览器连接仅对本机 DevTools 绕过系统代理，网站继续使用原有网络配置。

本机 Python 原始页面、任务和核对缓存位于现有服务数据根目录的 `PaperDailyWorkflow/python/`。界面只允许固定的启动、暂停、继续和交接操作，不接收任意命令或文件路径。审核服务忙会等待；达到既有额度会保留内容，不重置账本。未知计费结果保持挂起，明确可重试的失败仍最多三次。

自动来源审核使用 GitHub Secret `DEEPSEEK_API_KEY`，在发送付费请求前将证据指纹及预约写入远端账本。旧 `journal-library.js --collect --save` 直接入库入口已关闭，统一使用 `discover-collection.js --run --save-sources`。历史已完整记录不会因为上线而全部重新付费审核。
