# 第三阶段使用与交接说明

更新日期：2026-09-07。范围：本地长期保存、运行日志、状态与重试衔接、最近60天回查，以及明确的非论文资料筛选。

## 先说结论

现在程序不仅能试抓，也具备了“保存下来、下次接着更新”的能力。新版本先写到单独的位置，确认结构和文件校验值都正确后，才切换到新版本；历史文件不删除。

本阶段新增31项测试，与原有33项合计64项。测试使用临时文件夹和模拟来源，不联网、不读取密钥、不改旧 arXiv 数据。另有一次真实测试子进程的强制终止检查，不是实际断电或硬盘故障实验。

本轮没有执行真实论文入库，`data/journal-store/` 尚未初始化；没有配置密钥、生成翻译、创建每日任务、推送 Git 或部署网站。原网页仍未连接新论文库。

## 已完成的功能

- 默认回查最近60个自然日，包含北京时间今天；可手动指定天数、日期范围或一本期刊。
- 每刊分别查询两源，记录返回数、有效候选数、排除数、失败原因及耗时；继续使用已有超时和最多3次请求的重试规则。
- 来源原始页先暂存，再筛选、合并；筛除 `Front Matter`、目录、封面等明确行政资料，保留原因。
- 只用严格的标题规则排除，不因“没有摘要”删除论文，也不把包含 cover 等词的正常研究标题排除。
- 对标题明确提示更正、撤稿的记录予以保留，在审计文件中标为“可能的更正/撤稿通知”，不凭标题自动判定原论文已撤稿。
- 论文按首次发现年份分文件，日志按运行月份分文件；首次发现日期不被补抓改写，不删除60天以前的历史。
- 同日重跑保留独立日志，但不重复收录论文、不重复增加待翻译计数。
- 对损坏文件、缺失文件、错刊、重复 DOI、原文哈希不一致等情况停止采用新数据。
- 写入时加锁；两个遵守该机制的任务不能同时写库。异常退出残留的锁不会被自动抢占。

## 零基础用户可以怎样操作

在仓库 `G:\自动收集论文\paper-daily` 的终端中运行以下命令。不要使用旧版的 `npm start` 或 `npm run refresh` 来检查新系统，它们仍会启动旧 arXiv 流程。

### 1. 只检查，不联网、不改论文库

```powershell
node --test
node scripts/journals.js
node scripts/journal-library.js --status
```

分别是：跑自动测试、检查19刊名单、检查本地论文库并显示最近已提交日志。没有建立过论文库时，会显示 `initialized: false` 和数量0，这不是抓取结果，也不表示当天没有新论文。

也可以运行 `node scripts/journal-library.js --validate`，只读校验当前论文库。检查文件损坏时会报错，不会自动重新建一个空库。

### 2. 只想联网看看，不保存

继续使用第二阶段命令：

```powershell
node scripts/journals.js --collect --journal AER --from 2026-08-01 --to 2026-08-31 --max-pages 3
```

它仍只在内存中处理。本阶段的资料筛选也会用于这条试抓流程，但不会写正式库。

### 3. 决定开始积累真实论文时，明确联网并保存

下面的命令会创建或更新本地论文库，并发送真实来源请求。本轮开发没有代为执行。

```powershell
node scripts/journal-library.js --collect --save --journal AER
```

默认查询最近60天。把 `--journal AER` 换成 `--all` 可查询全部19刊。可以加 `--lookback-days 90` 改回查天数，或使用下面的明确日期范围，两种方式不能同时指定：

```powershell
node scripts/journal-library.js --collect --save --journal AER --from 2026-08-01 --to 2026-08-31
```

首次收集到的论文归入运行当天，不会按旧出版日期伪造往日“首次发现”。这不是回填过去的每日日历。

`--max-pages` 默认1000，是每个来源的页数安全上限。达到上限仍有下一页时会报告不完整，不会冒充“没有新增”；不要把它当作只取最新几条的限制功能。

### 4. 需要补跑时

正常手动再次运行就会重新查询并合并。若只想在今天还没完整成功时运行，可加：

```powershell
node scripts/journal-library.js --collect --save --all --only-if-needed
```

仅当今天所选期刊和日期范围已经被双源成功的运行覆盖，才会跳过。只查过 AER 不会导致其余18刊被跳过；部分失败也不会触发跳过。跳过会留下本地尝试记录，不追加一次虚假的正式采集成功日志。

这只是一次命令的判断规则，并没有安装每日定时任务。

## 数据在哪里，为什么不直接覆盖原文件

本地库在 `data/journal-store/`，与旧 arXiv 的 JSON 文件分开。

```text
journal-store/
  current.json                    当前正式版本的入口
  writer.lock                     正在写入时的锁；正常结束会移除
  attempts/<运行ID>/
    started.json                  开始时间、期刊和回查范围
    failed.json 或 skipped.json   提交前失败或按规则跳过时的诊断
  snapshots/<运行ID>/
    manifest.json                 本版本使用哪些文件及其校验值
    papers/YYYY.json              本次变化涉及的年度论文文件
    runs/YYYY-MM.json             本次追加后的月度运行日志
    audit.json                    去重冲突、排除理由、更正撤稿提示
    raw/<期刊>-<来源>.json         合并前暂存的来源页和拒收记录
```

这是需求书“年度论文、月度日志”建议结构的版本化实现。未变化的年度文件会继续引用旧版本的位置；新版本只写变化的分文件，再用一个小入口文件完成整体切换，避免某些年度更新了、另外一些还没更新。

文件写入完成后执行同步并回读校验，最后在同一目录重命名替换入口；若替换失败，不先删除旧入口。实现使用 Node 的文件同步与重命名接口。[Node 文件系统说明](https://nodejs.org/api/fs.html)

重要：备份必须复制整个 `journal-store/`，不能只复制最新的 `snapshots/<运行ID>/`，因为它可能引用更早版本的年度文件。旧论文、旧版本和暂存数据没有自动删除规则，磁盘使用会逐渐增加。

**目前该目录仍被 Git 忽略，不会随代码自动上传到 GitHub。** 本阶段实现的是本地持久保存，不是云备份。后续接 GitHub Actions 前，必须接通经过校验的数据导出、版本提交和恢复流程；不能把 Actions 的临时磁盘当成正式库。

## 四种结果怎样理解

| 状态 | 含义 | 本地保存行为 |
| --- | --- | --- |
| `success` | 所选期刊双源完整，有新增或内容变化 | 保存新论文版本和日志 |
| `no_updates` | 所选期刊双源完整，没有净新增或内容变化 | 保存本次日志；可能更新核对时间 |
| `partial_failure` | 存在失败、不完整或拒收记录，但仍有可用来源结果 | 保留有效资料，并明确记录失败 |
| `full_failure` | 无可用来源结果，或新数据结构校验失败 | 不采用新论文；能安全写日志时只追加失败日志 |

如果历史库已经损坏，或写盘/切换步骤失败，程序不切换入口；可写入的诊断放在 `attempts/`，不会为了追加日志而覆盖有问题的正式库。突然终止时可能只剩 `started.json`，没有结束记录。磁盘已满时连诊断文件也可能写不下，此时命令会报告失败。

输出中的 `committed: true` 只表示本次版本和日志提交到本地库；若状态是 `full_failure`，它不表示有新论文入库。网络来源的原始正文或完整错误堆栈不会出现在简要错误日志中。

`--status` 显示的是最近正式提交的日志，不保证包含尚未提交或突然中断的尝试。排查异常还要看 `attempts/`，不能只看上一条绿色成功状态。

## 出错时先做什么

- 显示 `LIBRARY_LOCKED`：先确认是否还有采集进程。不要看到锁文件就直接删除；如果任务已中断，先保留完整目录，再让开发者核查并解除残留锁。
- 显示 `CORRUPT_LIBRARY` 或 `MISSING_POINTER`：不要删除目录重来。先复制整个目录作为备份，检查最近可用的版本清单与文件；本阶段没有“一键恢复”，恢复需单独确认。
- 显示 `PAGE_LIMIT`、`RETRY_LATER` 或网络错误：已有数据仍保留，可稍后手动补跑。更大范围查询可能需要更多时间或触发公开接口限流。
- 文件占用、权限或空间不足：先处理存储问题，不手工清空 `current.json`。修复后再校验和补跑。

版本化保存可以降低程序中断造成半成品的风险，但不能代替异地备份。未验证真实掉电、硬盘损坏、网络共享盘语义或防病毒软件长期占用文件等环境。

2026-09-07，Windows 本地 `node --test`：64项通过，0项失败。新增测试覆盖：
